# Data Model: West End Dog-Inclusive Outing Planner

## DogPreferenceSet

Represents optional saved preferences for a dog.

**Fields**

- `id`: local unique identifier
- `dogName`: short display name; required only when saving
- `preferences.quieterAreas`: boolean
- `preferences.fewerDogs`: boolean
- `preferences.avoidCrowds`: boolean
- `preferences.easyWaterAccess`: boolean
- `preferences.noSpecificPreference`: boolean
- `updatedAt`: ISO date/time string

**Validation Rules**

- `dogName` is required before saving and should be short enough for mobile display.
- `noSpecificPreference` is mutually exclusive with the other preference flags.
- Temporary outing changes must not overwrite saved values unless the user explicitly saves.

**Relationships**

- May be selected by an `OutingPlan`.
- May be copied into `temporaryPreferences` for the current outing.

## ActivitySelection

Represents the user's selected outing activity types.

**Fields**

- `activityIds`: array containing one or more of `market`, `food`, `shopping`, `riversideWalk`,
  `restPicnic`
- `availableTimeMinutes`: selected time budget

**Validation Rules**

- At least one activity is required to generate an outing.
- If selected activities cannot fit the available time, the planner presents a simpler itinerary.

**Relationships**

- Used by `OutingPlan` generation.
- Matched against `Destination.activityTags`.

## Destination

Represents a curated West End prototype overlay destination.

**Fields**

- `id`: unique destination identifier
- `name`: display name
- `activityTags`: supported activity categories
- `coordinates`: latitude/longitude pair
- `summary`: short display copy
- `dogAccess.allowed`: allowed, limited, or unknown
- `dogAccess.whereAllowed`: short access location note
- `dogAccess.leashRequirement`: short leash note where applicable
- `sourceNote`: optional source or update note
- `suitabilityTags`: optional tags such as quiet, shaded, waterNearby, or crowdSensitive

**Validation Rules**

- Each destination must have coordinates suitable for display on the real West End base map.
- Access information must avoid implying live verification.
- Summary and access text must be short enough for mobile review cards.

**Relationships**

- Appears in one or more `OutingItinerary` stops.
- Connects to `WalkingRoute` stop order.

## Facility

Represents a curated support point overlay.

**Fields**

- `id`: unique facility identifier
- `type`: water, bin, seatingShade, toilet, parkingAccess
- `name`: optional display name
- `coordinates`: latitude/longitude pair
- `description`: short note
- `status`: available, limited, unknown, or simulated

**Validation Rules**

- Water and bin facilities must be available for active navigation defaults.
- Facility status must not imply live verification.

**Relationships**

- Referenced by route-step `facilityDistances`.
- Can appear as optional map layers or detail items.

## OutingItinerary

Represents the generated multi-stop outing.

**Fields**

- `id`: unique itinerary identifier
- `title`: display name
- `activityIds`: activity categories covered
- `availableTimeMinutes`: selected time budget
- `dogPreferenceSummary`: short applied preference summary
- `stopIds`: ordered destination identifiers
- `primaryRouteId`: linked walking route
- `weatherScenarioId`: linked weather context
- `notes`: optional short explanation of trade-offs

**Validation Rules**

- Must contain at least one destination and one route.
- Should cover selected activities where possible.
- Must remain believable within the selected available time.

**Relationships**

- Uses `Destination`, `WalkingRoute`, `WeatherScenario`, and optional `DogPreferenceSet`.

## WalkingRoute

Represents a predefined route overlay.

**Fields**

- `id`: unique route identifier
- `name`: display name
- `stopIds`: ordered destination identifiers
- `summary.distanceLabel`: approximate total distance
- `summary.durationLabel`: estimated duration
- `polyline`: ordered latitude/longitude points for the primary route
- `segments`: route segments with crowd level and styling metadata
- `steps`: manually advanceable route steps
- `alternativeRouteId`: optional Plan B route id

**Validation Rules**

- Route geometry is predefined and not generated by a routing engine.
- Total distance and duration are approximate labels.
- Manual route steps must be ordered and sufficient to demonstrate active navigation.

**Relationships**

- Belongs to an `OutingItinerary`.
- Contains `RouteStep` records.
- May reference an `AlternativeRoute`.

## RouteStep

Represents one simulated active-navigation position.

**Fields**

- `index`: step order
- `position`: latitude/longitude pair for current marker
- `nextDestinationId`: destination the user is heading toward
- `distanceToNextLabel`: approximate distance or time label
- `facilityDistances`: predefined labels for nearest water and nearest bin, with optional other
  facility labels
- `activeSegmentIds`: segment identifiers relevant at this step

**Validation Rules**

- Each step must have a next destination until the route is complete.
- Water and bin distance labels must be present for active navigation steps where relevant.
- Facility distances are predefined approximate values, not calculated live.

**Relationships**

- Belongs to `WalkingRoute`.
- May trigger a `ScenarioEvent`.

## AlternativeRoute

Represents a highlighted Plan B overlay.

**Fields**

- `id`: unique alternative route identifier
- `baseRouteId`: primary route it alternatives
- `polyline`: ordered latitude/longitude points
- `comparisonLabels`: short labels such as quieter, +4 min, or +300 m
- `summary`: short explanation for the user

**Validation Rules**

- Must be visually distinguishable from the current route.
- Comparison labels must remain short and decision-focused.
- Does not require production-grade route recalculation.

**Relationships**

- Referenced by `WalkingRoute.alternativeRouteId`.
- Shown by `ScenarioEvent` and `ContextualAlert`.

## WeatherScenario

Represents lightweight planning context.

**Fields**

- `id`: unique weather scenario identifier
- `label`: short weather label
- `temperatureLabel`: short temperature display
- `planningNote`: optional relevance note
- `simulated`: true

**Validation Rules**

- Weather must remain secondary to planning.
- Weather must be clearly presented as prototype context.

**Relationships**

- May be linked to an `OutingItinerary`.

## ScenarioEvent

Represents deterministic simulated dynamic behaviour.

**Fields**

- `id`: unique event identifier
- `type`: crowdChange, facilityStatus, routeAlert
- `routeId`: route where event applies
- `triggerStepIndex`: predefined route step where event appears
- `affectedSegmentIds`: route segments affected
- `message`: short alert copy
- `alternativeRouteId`: optional Plan B route
- `vibrationPattern`: optional vibration hint

**Validation Rules**

- Crowd-change event must trigger at the predefined step.
- Alert copy must be short and contextual.
- The event must work visually without vibration.

**Relationships**

- May create a `ContextualAlert`.
- May expose an `AlternativeRoute`.

## ContextualAlert

Represents the active alert shown to the user.

**Fields**

- `eventId`: linked scenario event
- `status`: hidden, visible, dismissed, keptCurrent, switchedPlanB
- `title`: short alert title
- `message`: short decision prompt
- `actions`: keep current route, view/switch Plan B

**Validation Rules**

- Alert appears only when the simulated condition affects the current outing.
- User must decide whether to keep or switch routes.
- Alert must not obscure the ability to continue navigation.

## State Transitions

```text
Planning -> Itinerary Review -> Active Navigation -> Crowd Alert Visible
Crowd Alert Visible -> Keep Current Route -> Active Navigation
Crowd Alert Visible -> Switch to Plan B -> Active Navigation on Plan B
Planning -> Save Dog Preferences -> Planning with Saved Dog
Saved Dog Selected -> Temporary Preference Change -> Current Outing Only
```
